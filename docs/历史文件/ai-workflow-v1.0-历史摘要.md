## v1.0 是什么

AI 协作开发的**单一线性流程**（v2.0 之前的版本），7 篇文档：

| 篇 | 主题 | 核心内容 |
|----|------|---------|
| 01 | 角色分工与文件体系 | 三角色：审查者（DeepSeek 唯一审查关卡）/ 架构师+开发（Opus，TDD 自检）/ 决策者（人，只拍板差异点） |
| 02 | 第零步：调研 | 开工前调研，产出调研笔记 |
| 03 | 第一步：编写计划 | 计划先行，BDD 驱动 |
| 04 | 第二步：迭代开发 | TDD 红绿重构、每功能点汇报 |
| 05 | 完整流程与核心原则 | 调研→计划→开发→收束 线性链 |
| 06 | 第三步：收束节点 | 四阶段（整理/测试/审计/验证）——v2.0 沿用 |
| 07 | 汇报 | worklog + STATUS 汇报体系——v2.0 沿用 |

## 与 v2.0 的关键差异

| 维度 | v1.0 | v2.0 |
|------|------|------|
| 任务模型 | 单一线性流程 | **双轨制**：长程任务 + 思考任务 |
| 模块分类 | 无 | 工程模块 vs 基础+功能模块 |
| 设计规范 | 分散 | 独立成篇（7 件套设计文件夹 + 8 节结构） |
| 验收标准 | 隐含 | 显式三级（功能点/收束节点/项目级） |
| 端到端 | 未覆盖完整链路 | PRD → BDD+TDD → 技术转换 → 模块划分 → 并行开发 |
| 部署 | 无 | 统一服务器部署全流程（09-部署规范） |

## 保留价值（为何留摘要）

1. **角色分工思想**："审查唯一性"（不自审）在 v2.0 中以"红蓝对抗/独立审查"形式延续
2. **收束节点四阶段**（整理/测试/审计/验证）v1.0 首创，v2.0 全盘继承
3. **汇报体系**（worklog + STATUS + 收束报告）源头在 v1.0
