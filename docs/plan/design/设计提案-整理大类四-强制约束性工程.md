# 设计提案：整理大类四 · 强制约束性工程

> 关联 PRD：不变量 C1-C6（B 组全部）
> 更新: 2026-08-13 | 状态: ✅ 已执行（提交 I 待入库）

## 背景

### 当前的设计
19 钩子（8 通用 + ruff/gitleaks/markdownlint/ecc + 9 commit-msg 治理）+ 5 阶段 CI + check_* 19 脚本 + 收束闸门 + 豁免日志；故障注入拦截率 ≥90% 有量化证明。

### 解决的问题
提交前拦截（格式/密钥/一致性/治理）、提交后拦截（CI 5 阶段）、收束硬闸门、豁免可审计。

## 目标
约束覆盖率矩阵成文且机器可核对；钩子注册单一真源（消除三处手同步）；commitlint 噪音修复；钩子失败输出带修复指引。

## 方案（六问结论）

| 问题 | 结论 |
|------|------|
| 当前存在的问题 | 无"规范 × 闸门 × 人工"覆盖率矩阵；commitlint config 警告噪音（技术债 #2） |
| 结构性问题 | 钩子注册散落三处（.pre-commit-config.yaml / ci.yml / _meta.yaml）无注册清单；本地/远端检查职责边界未成文 |
| 未考虑到的问题 | 钩子耗时无量化；新人被拦截无自救指引；规范→钩子→测试三步联动无强制提示 |
| 怎样解决 | ① 覆盖率矩阵文档 + 一致性校验脚本 ② _meta.yaml 增 hooks 段（真源投射）③ commitlint 降噪 ④ 失败文案标准化 |

## 影响范围
conventions/_meta.yaml、.pre-commit-config.yaml（渲染产物）、scripts/render_meta.py、docs/约束覆盖率矩阵.md（新增）、.commitlintrc/commitlint.config.js
