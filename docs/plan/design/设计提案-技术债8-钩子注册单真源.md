# 设计提案：技术债 #8 钩子注册单真源

> 更新: 2026-08-14 | 状态: ✅ 已实现并销账（rev_sha 真源投射，R2-06 驱动）

## 背景

钩子注册信息当前散落三处，靠纪律手同步：

1. `conventions/_meta.yaml` 的 `pre_commit` 段（钩子列表 + source）
2. `.pre-commit-config.yaml`（render_meta 渲染产物——但当前渲染只覆盖**部分**：rev/钩子列表的同步机制不完整）
3. `.github/workflows/ci.yml`（CI 与本地闸门同源要求，靠注释纪律）

红蓝对抗 R-02 暴露：scaffold pre-commit 的 gitleaks rev 漂移（v8.18.0）长期无人察觉——正是"三处手同步"缺机器校验的后果。当前已有 `check_template_drift` 的 rev 字段级校验 + `check_consistency` 的投影校验作为**事后检测**，但真源投射（一处改、处处自动同步）尚未实现。

## 目标

`_meta.yaml` 的 `pre_commit` 段成为钩子注册的**唯一手维护真源**：改一处 → `render_meta.py --render` 自动投射出 `.pre-commit-config.yaml` 的钩子列表/rev；CI 与本地闸门一致性由现有 check_consistency/check_template_drift 继续兜底。

## 方案

1. `_meta.yaml` 扩展 `pre_commit` 段：每钩子补 `rev`、`args`、`stages` 字段（现仅 id+source）
2. `render_meta.py` 增 `--render pre-commit`：从 `_meta.yaml` 生成完整 `.pre-commit-config.yaml`（保留 local 钩子的 entry 手写段——entry 命令与脚本文件强绑定，仍手维护但登记在 _meta）
3. `render_meta.py --check` 同步校验：生成产物与工作区文件逐字节一致（漂移即 FAIL）
4. 测试：`test_ci_contract` 同步调整（期望值改从 _meta 读取）；变异测试（改 _meta 钩子 → --check FAIL）

## 影响范围

conventions/_meta.yaml、scripts/render_meta.py、.pre-commit-config.yaml（变纯渲染产物）、tests/conventions/test_ci_contract.py、docs/templates/devguard/scripts/render_meta.py（镜像）

## 验收

- 改 _meta pre_commit 段 → render 后 .pre-commit-config.yaml 自动同步；--check 抓漂移
- 19 钩子注册经渲染产物与真源一致（机器校验，非纪律）
- 全量测试 + 三变异验证（ADR 0009：改真源钩子 → rc=1）
